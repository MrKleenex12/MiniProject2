# Reflection: nanocomp_meep

Meep is a widely used electromagnetic simulation package from MIT. Its timeline is U-shaped with 8 gaps of at least three months. In its early years it was mostly one person's project, which explains the gaps. Since 2014 it has grown into a busy project with many contributors.

The longest gap was 15 months, from December 2012 to February 2014, and it was hard to interpret from the commits before it. They are ordinary fixes by Steven Johnson, ending with "version bump for 1.2.1." Once a release is out and the code is stable, a single maintainer has little reason to keep committing. The project was not on GitHub yet, so there were no issues to check.

The real finding, though, is what happened right after the gap. In March 2014 the commits show "git conversion" and "add mailmap file," meaning the project had just moved to git and GitHub. Within weeks, outside users opened issues #1 through #7. This means moving to GitHub gave people a public place to report problems and contribute. The same maintainer restarted it (`stevenj` and `Steven G. Johnson` are the same person), but new people like Ardavan Oskooi drove its growth. The project is very Active today.
